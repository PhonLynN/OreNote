# DS 参考图实测排版尺寸

> 量于 2026-10-04，用 `scripts/` 下的量测脚本对 DS/OreNote 截图做像素墨量分析。
> **所有数字都是量出来的，不是估的** —— 依据见每条的"量法"。

## 0. 最重要的一条结论（2026-10-04 同一段文字双图对比）

用户提供了**同一段 NS 方程回复**在两边（DS App / OreNote）的截图，
`verification/dsref/ds_ns_2.jpg` 与 `mine_ns_2.jpg`。因为**文字内容完全一样**，
可以逐段做行数对比 —— 这是判断"字太大/太小"最硬的证据：

| 段落 | DS 行数 | OreNote 行数 | |
|---|---|---|---|
| 首段 | 3 | 3 | OK |
| 它想回答什么问题 | 4 | 4 | OK |
| 核心思想 | 2 | 2 | OK |
| 各项的物理含义 | 2 | 2 | OK |
| 为什么它这么出名 | 5 | 5 | OK |
| 顺带一提 | 2 | 2 | OK |
| （其余 7 段） | — | — | 全部 OK |

**14 段全部同行的数**。再结合正文可用宽占图宽的比例：

| | 正文可用宽 / 图宽 |
|---|---|
| DS | 665/798 = **0.833** |
| OreNote | 764/916 = **0.834** |

⇒ **字号与页边距已经和 DS 一致了。**

### ⚠️ 那么"尺寸问题"到底是什么

**不是字号，是块级结构没解析出来，导致内容挤在一起。** 具体见下表。

## 1. 结构差异清单（同一段文字，双图逐条对比）

| # | 差异 | DS | OreNote | 严重度 |
|---|---|---|---|---|
| 1 | **标题与正文粘连** | 标题独占一行，正文另起段 | `它想回答什么问题给定一堆流体…` **粘在同一行** | 🔴 最高 |
| 2 | **标题层级不分** | `##` 与 `###` 字号明显不同 | 所有标题**一样大**，看不出层级 | 🔴 高 |
| 3 | **粗体原样露出** | `**牛顿第二定律（F=ma）用在流体微团上**` → 粗体 | 前两处**原样露出 `**`**，后面的才被吃掉 | 🔴 高 |
| 4 | **表格左列公式丢失** | `ρ∂u/∂t`、`ρu·∇u`、`−∇p`、`μ∇²u`、`f` 全部渲染 | **左列全空** —— 单元格里的行内公式没渲染出来 | 🔴 高 |
| 5 | **粘连条目没拆开** | `-若 μ=0…` 独立成条 | 跟上一行粘着 | 🟡 中 |
| 6 | 表格外观 | 带外框 + 「表格」标签 + 图标 + 表头蓝竖线 | 灰底无框、无标签 | ⛔ **刻意不对齐**（见下） |
| 7 | 块级公式 | 居中、分数线上下叠、略大 | 居中、结构正确 | ✅ 已对齐 |
| 8 | 行内公式字体 | `u ρ p μ f` 数学斜体 | 同样数学斜体 | ✅ 已对齐 |

### 为什么"尺寸"会被误判成问题

结构没解析出来时，**多个块被压进一个段落** —— 视觉上就是
"标题跟正文糊在一起、上下没有留白"，非常容易被读成"字号/行距不对"。
而实测表明字号行距都是对的（14 段同行数）。

**所以对齐 DS 的下一步不是调 dp，是把 1~5 这几个解析缺陷修掉。**

## 2. 换算比怎么定（量测前提）

| | 值 | 来源 |
|---|---|---|
| DS 截图宽 | 798 px | `ds_ns_2.jpg` |
| DS 正文可用宽 | 665 px | 墨迹左右边界（12 条正文行取中位） |
| DS 正文左边距 | 51 px | 同上 |
| DS 行内行距 | **80.5 px** | 行带中心距中位数（n=51） |
| OreNote 行内行距 | **66.0 px** | 行带中心距中位数（n=56） |

⚠️ 两张截图的**设备像素密度不同**（798 vs 916 图宽），
所以行距的 px 值**不能直接比** —— 要先按图宽归一化：

| | 行距 / 图宽 |
|---|---|
| DS | 80.5/798 = **0.1009** |
| OreNote | 66.0/916 = **0.0721** |

⇒ **DS 的行距比我们松约 40%**（按图宽归一化后）。
这与"14 段同行数"并不矛盾：同行的数说明**字一样大**，
而行距是**另一维**。两者合起来说明：

> 我们的字和 DS 一样大，但**行距明显更紧**（相对松 40%）。

这与上一轮在 `ref.jpg` 上量出的结论（我们用 25.6dp、DS 约 21.3dp）
**方向相反**，说明上一轮的换算比 k 用错了基准 —— 那次把不同密度的
两张图直接按"汉字 px ÷ 我们的 sp"换算，而 `ref.jpg` 是 968px 宽的
另一台设备截图。**以本轮的双图同行数对比为准**（同一段文字，最硬）。

## 4. ⛔ 表格外观：**刻意不跟 DS 对齐**（用户 2026-10-04 明确）

这是唯一一条"知道 DS 长什么样、但选择不一样"的项，写在这里防止以后有人顺手改过去。

| | DS App | **我们要的** |
|---|---|---|
| 外框 | 有圆角外框 | **无外框** |
| 背景 | 有卡片底色 | **无背景**（与正文同底） |
| 「表格」标签 + 图标 | 有（表格上方一条小标签栏） | **不要** |
| 表头 | 有蓝色左竖线装饰 | 不加 |
| 分割线 | 表头下一条 + 内部竖线 | **只有水平分割线**（每行之间），**不要竖线** |

用户原话：「表格我还是希望用只有水平分割线且无外框无背景的表格，就这一点和 ds 不一致」。

实现对应：`MarkdownTable` —— 无外框、无底色，`TableRow` 之间用 `Divider(totalWidth)`
画 1dp 水平线（最后一行不画），列之间只用 `TABLE_COL_GAP = 12.dp` 的留白分隔。

> ⚠️ 与"外观"无关、**必须修**的是表格的**内容渲染**：
> `mine_ns_2.jpg` 里表格左列（`ρ∂u/∂t` 等公式）**整列为空** ——
> 那是单元格行内公式没渲染出来的缺陷，不是外观取舍。见第 3 节第 4 条。

## 换算比怎么定（关键前提）

不能拍脑袋取一个 dp/px 系数。正确做法是**先让字一样大**：

| | 值 | 来源 |
|---|---|---|
| DS 截图宽 | 968 px | `ref.jpg` 实际尺寸 |
| iPhone 逻辑宽 | 440 pt | 968 / 2.2 |
| **DS 汉字步进（advance）** | **52.5 px** | 列表行 6 个完整汉字块的中心距中位数 |
| 我们的正文字号 | `AiTypo.body.fontSize` sp | 代码 |

⇒ **换算比 k = 52.5 / fontSize(sp)**

⚠️ 不要用"行高对齐"来定 k —— 那等于默认接受字号差异，而目标是"跟 DS 一样"。

## 一、行内行距（同一段里相邻基线距）

| 项 | DS 实测 | 量法 |
|---|---|---|
| **行内行距** | **70.0 px** | 横向墨量投影切成行带，相邻行带中心距；70.0 出现 7 次且高度一致（NS 正文那一大段） |

## 二、块间距（相邻行带中心距 ≥120px 的那一簇）

| 值 | 出现次数 | 推测对应 |
|---|---|---|
| 136.0 px | 1 | 标题↔正文 |
| 152.5 px | 1 | — |
| 176.0 px | 1 | 段落↔段落 |
| 313.0 / 323.0 px | 4 | 分隔线 `---` 两侧 |

## 三、列表

| 项 | DS 实测 | 量法 |
|---|---|---|
| 列表项间距 | 见"块间距"表（105px 一档） | 相邻圆点行带中心距 |
| **圆点缩进** | 圆点 x ≈ 43，正文 x ≈ 120（待复核） | 纵向投影找圆点与首字 |
| 圆点字号 | 明显小于正文（`•` x≈43..49，宽 ~7px） | 单块宽度 |

## 四、公式

| 项 | DS 实测 | 量法 |
|---|---|---|
| 行内公式字号 | 与正文**同高**（数学斜体字形） | 行带高度 |
| 块级公式字号 | 比正文略大 | 行带高度 vs 正文行带 |
| 块级公式居中 | 是（`∇·u = 0` 那行墨迹 x=508..885，明显居中） | 墨迹水平跨度在页宽中的位置 |

## 五、我们与 DS 的差距（换算后）

| 项 | DS 实测 | 我们当前 | 差 | 依据强度 |
|---|---|---|---|---|
| **行内行距** | 21.33 dp | **25.6 dp**（`AiTypo.body.lineHeight` = 16×1.60） | **+4.27 dp（偏松 20%）** | ✅ 实测 |
| 段落额外留白 | 32.30 dp | 30.4 dp（`gapBefore` = unit×1.9） | −1.90 dp | ✅ 实测 |
| 列表项额外留白 | 10.67 dp | 12.8 dp（unit×0.8） | +2.13 dp | ✅ 实测 |
| 标题前额外留白 | 20.11 dp | 20.8 dp（unit×1.3） | +0.69 dp | ✅ 实测 |
| 引用 / 表格 / 任务 / 代码块 | **无对照物** | — | — | ❌ 缺素材 |

**主要结论：块间距（段/列表/标题）基本已经对齐，真正偏差大的是"行内行距"——
我们比 DS 松 20%。** 行距一松，同样的段间距相对就不显眼，
整段文字读起来是一片灰；DS 是"紧行距 + 明显段距"，层次对比更强。

> ⚠️ 2026-10-04 用户决定**先不动行高**。所以上表只是结论，
> 代码里的 25.6dp **暂时保持原样**，等确认后再改。
